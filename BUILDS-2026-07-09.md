# Builds produced in the 2026-07-07 draw-issue session (branch perf-fps)

Goal: the draw tier of PLAN-OPTIMIZATION.md — cut the in-fight draw ~33%
(pure CPU command issue), continuing from the play4/ADPCM-offload state.

## The build to flash

**`mvs64/mvs64-samsho2-perf-fps-play5.z64`** — clean play build (no
diagnostics, no scripted input) with the fix-layer empty-tile skip on top of
the play4 configuration (RSP ADPCM offload, FM on CPU).

## What landed

| Commit | Change | Gate | In-fight effect |
|---|---|---|---|
| 21230e5 | [PERF2] draw profiling + fix-layer empty-tile skip | PC pixel gate 21/21 byte-identical; ares 300s content-matched fights | **22.9 → 29.3 fps** (draw 33→23, cells drawn 1120→~170) |

The [PERF2] profile that found it (in-fight medians, 0.01%-of-frame units):
draw 33% = fix 15.5% + sprite walk 7.2% + crom hash 5.9% + rspq writes 2.7%.
The fix layer drew all 1120 map cells every frame because "blank" cells hold
nonzero tile codes whose pixels are all index 0 (transparent in every
palette, since pal_convert forces color 0 alpha to 0). `srom_tile_empty`
learns per-tile emptiness on first sight (ROM-stable per SROM bank) and
render_fix skips those draws forever. Pixel-identical by construction and by
measurement (21/21 scripted-input screenshots byte-identical vs HEAD).

## Closed with measurement (reverted, not on the branch)

| Strategy | in-fight | why it lost |
|---|---|---|
| batched draw records: CPU cached arena + one rspq cmd per 32 records, RSP DMAs + replays through the same per-tile path | 20.9 (vs 29.3) | write-allocate dcache miss per arena line (rspq bucket 292→531) |
| + CACHE 0xD create-dirty-exclusive on record groups + direct-mapped L1 in front of the crom hash | 20.2, snd/m68k +10% | a 7-12KB/frame streaming write sweep + 16KB L1 through the 8KB direct-mapped dcache evicts every other subsystem's hot data; the L1 adds a guaranteed miss while the robin-hood hash at 31% load already averages ~1.2 probes |

Lesson (same class as the -O3/-Os icache results): on the VR4300 the
uncached rspq_write path pollutes nothing and is near-optimal; every new
CPU-side table/arena taxes the whole emulator through the tiny direct-mapped
caches. Also noted: any deferred-consumption draw scheme has a latent
correctness hazard — a mid-frame forced sprite-cache eviction can recycle a
pixel slot that an in-flight record still references.

## Where the frame goes now (in-fight, content-matched fights)

~29.3 fps median. Split: snd ~121% (FM+Z80+SSG on CPU — the dominant wall),
m68k ~66%, draw ~23% (fix 6.3, walk 7.2, cache 5.7, rspq 2.9), io ~6%.
